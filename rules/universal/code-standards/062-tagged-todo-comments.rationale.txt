# Why tagged todo comments (Magnus, 2026-11-09, in JAStudio)

Magnus: "when a todo clearly relates to a piece of code I find comments like this very helpful", and agreed to everything in
the proposal this rule records. Before it, what an agent found and didn't fix went into its end-of-task summary only, where
it was read once and lost; the documents' todo lists suit work that spans files, not a duplication in one method.

What decided it:
- A comment at the code is seen exactly when it matters: by whoever reads or changes that code next, human or agent.
- It moves with the code when the code is refactored.
- Rider lists every one in its TODO window, filtered by tag, so Magnus sees them without asking.
- An agent finds them all with one grep using the same patterns. Rider's MCP has no tool for the TODO window (checked
  2026-11-09), and none is needed.

The meanings of `review:`, `wip:` and `urgent:` are Magnus's own, as he uses them (2026-11-09). `review:rebuttal:` and
`todo:docs:` exist in his Rider patterns; their use wasn't discussed, so the rule leaves them to him.

`review-naming:` was added 2026-11-14 (Magnus, in JAStudio), when an agent proposed marking the naming calls it makes on
its own with `review:` comments for his pass: "Use //review-naming: for this from now on." And: "Any review comment that
is only about the name of something would use this new tag. If you want to clarify an area to make the comments more
searchable you could add it after the : //review-naming:matching:". The agent first saved it as a memory; Magnus: "It
should be in rules, not a memory I figure." Rider's `review:` pattern requires the colon right after "review", so it
doesn't list these: Rider needs a pattern for the tag, such as `(?<=\W|^)(?<TAG>REVIEW-NAMING:)(.*)`.

Where the patterns are: Magnus keeps his in one settings file of his own, which covers every solution and every Rider
version on his machine (2026-11-14: "I want all of them in the shared\vAny settings file"); a user-level rule there says
which file and how to add to it. A solution's settings override the user's, so a copy of the patterns in a solution's
`.DotSettings` hides later changes to his own: JAStudio's had one until that day, and Compze's
`CompzeResharperSettings.DotSettings` still did. The agent first wrote that each solution needs the pattern, having read
only the solution's file.

`todo:compze:` was added 2026-11-10 with the rule "Compze is our code" (`../004-compze-is-our-code.md`); its sidecar
says why.
