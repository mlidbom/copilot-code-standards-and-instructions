# Fixing bad rules: the worklist

Started 2026-11-14 in JAStudio, by Magnus and the session he named fix-bad-claude-rules. The shared rules were mostly
written in Deskmancer, for the models of that time, and several now override the agent's judgment for the worse. Why,
and the first cases, are in `universal/000-tell-me-when-a-rule-gets-in-the-way.rationale.txt` and
`universal/code-standards/007-ubiquitous-language.rationale.txt`.

This is not a rule, and it isn't loaded: a `.txt` outside the linked folders. Delete it when the work is done.

## How each step goes (Magnus, 2026-11-14)

1. The agent makes the step's changes, leaves them unstaged, and prepares the commit message, as the user-level rule
   `preparing-a-commit-for-magnus-to-make.md` says.
2. Magnus reads the diff: "Looking at the git diff is much easier for me than reading your free text description." He
   stages each file as he approves it, and commits in Git Extensions.
3. He pushes the catalog himself. When he says he has, the agent starts the next step.
4. The catalog's pin in the consuming repository is recorded once, when the work is done. Magnus, 2026-11-14: "One
   commit in the parent repo for every step here is not helpful." So meanwhile the agent fetches the catalog with git
   itself, not with the pull and push scripts, which commit the pin.

## What guides the changes

- **Remove before adding.** When a rule misfires, find the sentence that caused it and cut or soften it. A rule that
  corrects a rule comes last.
- **Keep what states Magnus's taste where it isn't the mainstream's,** and what counters something the agent really does
  otherwise. Cut what the agent's judgment gives anyway, and what tells it to distrust that judgment.
- **Force is for hard limits:** irreversible harm, such as changing external environments without approval.
- **Not starting to change code, rules or design documents without a clear instruction stays at full force.** Agents
  lean toward acting.

## Testing a change, not yet tried

Replaying a known failure, such as the add-on question, to fresh agents under the old and the new wording, and
comparing.

- **An agent started from a session gets the rules as they were when that session started,** not as they are on disk
  (checked 2026-11-14). It listed the 56 rule files and quoted one verbatim, but didn't have a rule written earlier in
  that session. Whether it sees an edit to a rule it does have isn't checked.
- **So the old wording can be replayed from a session that predates the change, and the new wording needs a new
  session,** such as `claude -p` run in the checkout. Not tried.
- **Each such agent costs about 100,000 tokens to start,** rules and tools included.
