## Where the discussion stands

Magnus asked whether JAStudio's .NET code should run inside Anki at all. Over several turns the two of you agreed on this:

- JAStudio becomes a program of its own. The Anki add-on becomes pure Python, with no .NET in Anki.
- HTTP with JSON both ways: the add-on runs a minimal HTTP server on loopback, and calls the Kestrel server that JAStudio already runs for rendering cards.
- No instant notifications from Anki. A Sync button in a Studying view is enough, plus one read at start. Study-notes are written at a sync only.
- Most of the Qt menus go.
- JAStudio should eventually be able to work with other studying integrations than Anki. So Core should speak about studying, and nothing that is generic about studying should be named after Anki. Anki's names stay in JAStudio.Anki and on the wire.
- Inside JAStudio, the studying integration might be reached through Compze.Tessaging. That is not decided.

In your previous message you listed what would change for Magnus as a user, and three things you were unsure of: where raw notes arrive for import, how a tommand would find the right studying integration once there are two, and that Anki's changes would show in JAStudio only after a sync.
